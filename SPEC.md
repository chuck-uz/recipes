## 1. Суть продукта

Личная поваренная книга на телефоне. Рецепты рождаются в чате с Claude, проверяются на кухне, и понравившиеся одной фразой («отправь этот рецепт в гит») уходят в этот репозиторий. Приложение подтягивает новые и изменённые рецепты и показывает их интерактивно — с русскими единицами измерения, пересчётом порций и пошаговым режимом готовки.

**Ключевой принцип:** рецепты — это контент, а не код. Новый рецепт не требует пересборки приложения; репозиторий — единственный источник правды.

### Цели

- Ноль ручной работы между «понравилось» и «есть в приложении».
- Полностью офлайн-работа на кухне; синхронизация при запуске и по свайпу вниз.
- Единицы измерения по-русски, с правильными склонениями и понятными дробями.
- Таймеры, которые срабатывают всегда — за счёт того, что их ведёт системное приложение «Часы», а не мы.

### Не входит в первую версию

Аккаунты и облачный бэкенд, публикация в Google Play, iOS, редактирование рецептов внутри приложения, фотографии, список покупок, история готовки и оценки. См. раздел 10.

## 2. Сквозной сценарий

1. Денис просит рецепт в чате Claude. Claude отвечает текстом, как обычно.
2. Денис готовит. Понравилось — пишет: «отправь этот рецепт в гит».
3. Claude переводит рецепт в JSON по схеме (раздел 5) и коммитит `recipes/<id>.json` в `main`. Правки — тем же путём, с увеличением `version`.
4. GitHub Actions проверяет файл по схеме и правилам, пересобирает `index.json`. Невалидный рецепт в индекс не попадает, и Claude видит ошибку.
5. Приложение при запуске или по свайпу вниз сверяет индекс, скачивает только новое и показывает «Обновлено: N рецептов».
6. Денис открывает рецепт, выставляет порции, включает режим готовки, запускает таймеры.

Ожидаемая задержка между пушем и появлением в приложении — до нескольких минут (кеш GitHub).

## 3. Архитектура

| Компонент | Назначение | Решение |
|---|---|---|
| Репозиторий | Контент, схема, исходники, CI | `github.com/chuck-uz/recipes`, публичный, ветка `main` |
| Контент | Один JSON на рецепт + автогенерируемый `index.json` | `recipes/`, схема `schema/recipe.schema.json` |
| CI | Валидация и индекс; сборка APK по тегу | Два workflow в `.github/workflows/` |
| Канал «чат → Git» | Claude коммитит рецепты из чата | GitHub-коннектор в Claude (OAuth). Запасной путь — Cowork с клоном, либо вставка JSON через веб-интерфейс GitHub |
| Приложение | Читает индекс и рецепты, хранит локально, работает офлайн | React Native + Expo, TypeScript |
| Дистрибуция | APK из GitHub Releases | Подписанный APK, без Google Play |

### Стек — зафиксирован

**React Native + Expo (TypeScript).** Развилки с Kotlin больше нет: она существовала только из-за фоновых таймеров, а таймеры отданы системным часам (раздел 4.5).

Следствие: нужные нативные возможности — запуск системного интента (`expo-intent-launcher`) и незатухающий экран (`expo-keep-awake`) — входят в состав Expo Go. Повседневная разработка идёт в Expo Go без dev-сборок; собственный APK нужен только для релиза.

Логика единиц, склонений и масштабирования живёт в отдельном пакете `recipe-core` и используется и приложением, и валидатором в CI — одна реализация, одни тесты.

### Структура репозитория

```
recipes/
  SPEC.md                    # этот файл — источник правды
  CLAUDE.md                  # правила для Claude: формат, команды, запреты
  recipes/                   # контент: один JSON на рецепт
  index.json                 # генерируется CI, вручную не редактируется
  schema/recipe.schema.json  # JSON Schema рецепта
  packages/recipe-core/      # единицы, склонения, масштабирование, валидация (TS + тесты)
  app/                       # приложение (Expo)
    app/                     # экраны: expo-router ищет роуты в каталоге app
    src/                     # синхронизация, хранилище, таймеры, тема
  .github/workflows/
    content.yml              # валидация + индекс при изменении recipes/
    release.yml              # сборка APK по тегу v*, публикация в Releases
```

## 4. Функциональные требования приложения

Первая версия содержит весь этот раздел целиком.

### 4.1 Список рецептов

- Карточки: название, теги, время приготовления, порции по умолчанию.
- Поиск по названию; фильтр по тегам.
- Индикатор «новое» для рецептов, добавленных с последней синхронизации.
- Свайп вниз — синхронизация, с понятным итогом: «Обновлено: 2 рецепта» / «Всё актуально» / «Нет сети — показаны сохранённые».

### 4.2 Карточка рецепта

- Описание, теги, общее время, заметки.
- Регулятор порций (−/+ и ввод числа), диапазон **1–12**. Все количества пересчитываются мгновенно, в том числе внутри текста шагов.
- Список ингредиентов с чекбоксами «подготовил».
- Кнопка «Готовить».

### 4.3 Единицы измерения и отображение количеств

Хранятся коды, отображается русский текст.

| Код | 1 | 2–4 | 5+ | дробь | Сокращение |
|---|---|---|---|---|---|
| `tsp` | чайная ложка | чайные ложки | чайных ложек | чайной ложки | ч. л. |
| `tbsp` | столовая ложка | столовые ложки | столовых ложек | столовой ложки | ст. л. |
| `pinch` | щепотка | щепотки | щепоток | щепотки | — |
| `g` / `kg` | г / кг — без склонения | | | | |
| `ml` / `l` | мл / л — без склонения | | | | |
| `pcs` | шт. — счётное слово живёт в названии ингредиента («зубчик чеснока», «картофель средний») | | | | |
| `to_taste` | «по вкусу» — не масштабируется, без `amount` | | | | |

Форм четыре, а не три: дробное количество требует родительного падежа единственного числа («½ чайной ложки»), и это не та же форма, что у пяти и больше («чайных ложек»).

Единица `cup` («стакан») в схему **не входит**: в быту это и 200, и 250 мл, а при дробном масштабировании она бесполезна. Объёмы пишутся в мл, сыпучее — в граммах.

**Правила отображения:**

- Настройка «полные слова / сокращения», по умолчанию — **полные слова**.
- Дроби: 0,25 → ¼, 0,5 → ½, 0,75 → ¾; смешанные — «1½». Трети (⅓, ⅔) не используются: они несовместимы с шагом округления ложек. Остальное — десятичные с запятой, не более одного знака.
- Дробное количество ложек склоняется как родительный падеж единственного числа: «½ чайной ложки», «1½ столовой ложки», «2½ столовой ложки».
- Округление после масштабирования: граммы и миллилитры — до целых, свыше 100 — до 5; килограммы и литры — до десятых; штуки и щепотки — до ½; ложки — до ¼. Количество никогда не опускается ниже одного шага округления: «0 г соли» — бессмысленный результат пересчёта.
- Дроби показываются только у единиц с дробным шагом округления — ложки, штуки, щепотки. У метрических единиц вид десятичный, иначе «1½ кг» соседствовало бы с «1,3 кг» в одном списке.
- Крупные количества показываются укрупнённо: 1000 г → «1 кг», 1500 мл → «1,5 л». Только для круглых значений, чтобы не превращать 1750 г в «1,8 кг».
- Логика покрыта автотестами по таблице «вход → ожидаемая строка». Тесты — часть приёмки.

### 4.4 Режим готовки

- Один шаг на экран: крупный заголовок, текст с подставленными количествами, кнопки «Назад / Далее», прогресс «3 из 6». Крупные зоны нажатия — экран смотрят издалека и мокрыми руками.
- Экран не гаснет, пока режим активен.
- Если у шага есть длительность — кнопка «Запустить таймер» (раздел 4.5).
- Быстрый доступ к списку ингредиентов шторкой, без выхода из режима.
- **Сессия готовки сохраняется:** порции, текущий шаг и отмеченные ингредиенты переживают сворачивание и перезапуск приложения. При открытии рецепта с незакрытой сессией моложе **6 часов** предлагается «Продолжить с шага N» или «Начать заново». Старше 6 часов — рецепт открывается чистым.

### 4.5 Таймеры

Таймеры ведёт **системное приложение «Часы»**, а не мы. Приложение лишь заводит их стандартным интентом Android `AlarmClock.ACTION_SET_TIMER`, передавая длительность, подпись (заголовок шага) и флаг тихого запуска.

- Нажатие «Запустить таймер» заводит таймер **не покидая рецепт** (`EXTRA_SKIP_UI = true`); внизу всплывает подтверждение «Таймер 30 мин — Второй бульон».
- Время можно поправить перед запуском.
- В шапке режима готовки живёт строка активных таймеров — «⏱ Второй бульон — 12:34» — с обратным отсчётом, вычисляемым арифметикой по абсолютному времени окончания. Нажатие открывает «Часы».
- Звонок, повтор, отсрочка, отмена — забота системных часов. Надёжность равна надёжности штатного будильника телефона.
- Целевое устройство — Samsung Galaxy S24 FE / Android 16: штатные «Часы» Samsung корректно принимают длительность и показывают переданную подпись.

Никаких foreground service, разрешений на точные будильники и собственных уведомлений в приложении нет. Но два объявления в манифесте всё же обязательны, и без них интент молча отвергается:

- разрешение `com.android.alarm.permission.SET_ALARM` — интент таймера защищён им;
- блок `queries` с действиями `SET_TIMER` и `SHOW_TIMERS` — с Android 11 приложение иначе не «видит» штатные «Часы».

Отправка интента идёт каскадом: сначала тихий запуск, затем с открытием «Часов», затем запасным механизмом. Если не сработало ничего, приложение показывает причины всех попыток, а не общую фразу — иначе «не запустился» неотличимо от «нет разрешения».

### 4.6 Синхронизация и хранение

- Источник: `index.json` в репозитории. URL и ветка задаются в настройках, значение по умолчанию зашито.
- **Загрузка идёт через `raw.githubusercontent.com`.** Это CDN, а не GitHub API, и лимит в 60 запросов в час к нему не относится — поэтому архив ветки не нужен: даже первая синхронизация полусотни рецептов остаётся полусотней маленьких запросов, которые идут пачками по шесть. Единственное обращение к самому API — проверка новой версии приложения, не чаще раза в сутки.
- **Инкрементально:** скачать индекс → сравнить `sha256` с локальными → скачать только изменившиеся файлы → заменить локальные копии. `index.json` сохраняется **последним**: если загрузка оборвалась на середине, следующая синхронизация просто доделает работу.
- При ручном обновлении свайпом к адресу добавляется уникальный параметр, чтобы обойти кеш CDN; при запуске приложения — нет.
- Рецепты, исчезнувшие из индекса, помечаются «в архиве» и скрываются, но локально не удаляются без подтверждения.
- Всё содержимое хранится локально; приложение полноценно работает без сети.
- Приватный репозиторий не используется, но настройка токена только на чтение предусмотрена на будущее: хранится в защищённом хранилище устройства, в код и репозиторий не попадает никогда. При ответе 401 приложение говорит «токен истёк», а не «нет сети».
- Рецепт со `schemaVersion` больше поддерживаемой пропускается с пометкой «нужна новая версия приложения». Падать нельзя.

### 4.7 Обновление приложения

При запуске, не чаще раза в сутки, приложение сравнивает свою версию с последним релизом в GitHub Releases и показывает баннер «Доступна версия X — скачать». Установка вручную из скачанного APK.

### 4.8 Настройки

Адрес репозитория и ветка, токен (опционально), полные слова / сокращения единиц, тема (системная / светлая / тёмная), «Синхронизировать сейчас», «Проверить таймер (10 секунд)», версия приложения.

Проверка таймера нужна потому, что интент обрабатывает штатное приложение «Часы», а прошивки делают это по-разному: десять секунд — самый дешёвый способ убедиться, что на конкретном телефоне всё в порядке.

## 5. Формат рецепта (контракт «чат ↔ приложение»)

Один файл `recipes/<id>.json`; `id` — латиница и дефисы, совпадает с именем файла.

```json
{
  "schemaVersion": 1,
  "id": "kurinyj-sup-dieticheskij",
  "version": 1,
  "title": "Лёгкий куриный суп",
  "description": "Диетический суп на втором бульоне, без зажарки и специй.",
  "tags": ["суп", "диетическое", "курица"],
  "servings": 4,
  "totalTimeMin": 70,
  "ingredients": [
    { "id": "chicken", "name": "куриная грудка без кожи и костей", "amount": 500, "unit": "g" },
    { "id": "water",   "name": "вода", "amount": 2, "unit": "l", "scalable": false },
    { "id": "potato",  "name": "картофель средний", "amount": 2, "unit": "pcs" },
    { "id": "bayleaf", "name": "лавровый лист", "amount": 2, "unit": "pcs", "scalable": false },
    { "id": "salt",    "name": "соль", "amount": 1, "unit": "tsp" }
  ],
  "steps": [
    {
      "id": "s1",
      "title": "Первый бульон — слить",
      "text": "Положите куриную грудку ({chicken}) в кастрюлю, залейте холодной водой, доведите до кипения и варите 5 минут. Слейте воду.",
      "timerSec": 300
    },
    {
      "id": "s2",
      "title": "Второй бульон",
      "text": "Залейте курицу свежей водой ({water}) и варите на слабом огне 30 минут.",
      "timerSec": 1800
    }
  ],
  "notes": "",
  "createdAt": "2026-08-30",
  "updatedAt": "2026-08-30",
  "source": "claude-chat"
}
```

### Правила

- **Плейсхолдер `{ingredientId}` разворачивается только в «количество + единица»** — например, «500 г». Название ингредиента пишется в тексте шага словами, в нужном падеже, а плейсхолдер стоит рядом в скобках или через тире. Приложение не склоняет названия и не пытается их подставлять.
- `amount` — число, дроби допустимы. `unit` — только коды из таблицы 4.3. У `to_taste` поля `amount` нет.
- `scalable` — необязательное, по умолчанию `true`. Ставится `false` там, где линейный пересчёт врёт: штучные пряности (лавровый лист), вода для варки, масло для жарки. Такой ингредиент показывается без пересчёта и помечается визуально.
- `timerSec` — только у шагов с ожиданием (варка, настаивание, маринование). При масштабировании порций не меняется.
- Изменение рецепта — увеличить `version` и `updatedAt`; `id` не меняется.
- `index.json` (генерируется CI): список `{ id, title, tags, totalTimeMin, servings, updatedAt, file, sha256 }` и `generatedAt`.
- Дублирующийся `id` — ошибка CI с внятным сообщением, а не молчаливая перезапись.

## 6. Канал «чат → Git» и правила для Claude

Правила для Claude вынесены в [CLAUDE.md](CLAUDE.md) — он же читается в каждой сессии.

Валидация — **единственная ответственность CI**. Claude не проверяет правила «в уме»: он коммитит и читает результат сборки. Иначе появляется третья реализация тех же правил, которая обязательно разойдётся с первыми двумя.

Подключение: официальный GitHub MCP-сервер добавляется в Claude как кастомный коннектор (OAuth). Если из чата настроить не удастся — запасные пути: сессия Cowork с клоном репозитория, либо вставка готового JSON через веб-интерфейс GitHub прямо с телефона.

## 7. CI и дистрибуция

**`content.yml`** — при изменении `recipes/` или `schema/`: валидация всех рецептов по JSON Schema и правилам из `recipe-core`, генерация `index.json`, коммит индекса от имени бота. Красный статус означает, что рецепт не попал в приложение.

Две обязательные защиты:
- `paths-ignore: index.json` — иначе коммит бота бесконечно перезапускает workflow сам на себя.
- `concurrency` — иначе два быстрых пуша подряд подерутся при push индекса.

**`app.yml`** — при изменении `app/` или `packages/recipe-core/`: проверка типов и полная сборка бандла Metro. Сборка бандла ловит то, чего не видит `tsc`: ошибки резолва `recipe-core` из-за границы корня приложения и опечатки в путях роутов.

**`release.yml`** — по тегу `v*`: `expo prebuild`, сборка релизного APK в раннере GitHub Actions, подпись, публикация в Releases с changelog. У публичного репозитория минуты Actions бесплатны и без очереди; EAS Build не используется, чтобы ключ подписи не хранился в двух местах. Сборка занимает около пятнадцати минут.

Три вещи, встроенные в workflow намеренно:

- **Тег обязан совпадать с версией** в `app/app.json`, иначе сборка падает сразу. Иначе однажды `v0.3.0` окажется приложением версии 0.2.1.
- **Проверка подписи после сборки.** Без неё можно годами публиковать APK, подписанный отладочным ключом, и узнать об этом только тогда, когда очередное обновление откажется вставать поверх установленного.
- **Только архитектура `arm64-v8a`.** Универсальный APK несёт ещё три набора библиотек, которых нет ни в одном современном телефоне, и весит втрое больше.

**Как выпустить версию:** поднять `version` и `android.versionCode` в `app/app.json`, закоммитить, поставить тег `v<версия>` и запушить его. Всё остальное сделает CI.

**Подпись:** ключ `recipes-release.keystore` создан один раз, лежит в секретах репозитория (`RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`) и в личной резервной копии владельца. Отпечаток сертификата SHA-256: `05fd2333334f9ec6852316c9420cfb1bedc60cc2af54308b7ad587c040c3180e`.

**Установка:** скачать APK из Releases, один раз разрешить установку из этого источника.

## 8. Приватность

Репозиторий публичный, поэтому действует жёсткое правило: **в файлах рецептов нет медицинского контекста, диагнозов, имён и любых персональных деталей.** Рецепт может быть диетическим — но не может объяснять, чью и какую болезнь он обслуживает.

Правило подкреплено механически: `recipe-core` содержит проверку на стоп-слова, `content.yml` красит сборку при срабатывании.

- Обезличенные медицинские термины (диагнозы, «анализы», «врач», «УЗИ» и подобные) лежат списком в репозитории.
- **Личные имена передаются валидатору через секрет GitHub Actions** — список имён в публичном репозитории сам по себе раскрывал бы то, что должен скрывать. Локально эта часть проверки просто пропускается.

Поле `notes` — только про готовку, и только если о заметке попросили явно.

Git помнит всё: проверка срабатывает уже после пуша. Если что-то проскочило — правится amend'ом и force-push немедленно, а не следующим коммитом.

## 9. Нефункциональные требования

- Целевое устройство: Samsung Galaxy S24 FE, Android 16. `targetSdk` 36, только портретная ориентация.
- Язык интерфейса — русский. Тема по системной, с ручным переключением.
- Открытие любого экрана офлайн — мгновенно; синхронизация не блокирует интерфейс.
- Никакой аналитики, трекинга и сторонних сервисов, кроме GitHub.
- Автотестами покрыты: пересчёт порций, склонения и отображение единиц, а также форма `index.json` как контракт между CI и приложением.

## 11. План работ

**Фаза 1 — Контент и пайплайн.** Структура репозитория, `SPEC.md`, `CLAUDE.md`, JSON Schema, `recipe-core` (сначала тесты по таблице 4.3, потом реализация), стоп-слова, `content.yml`. Первый рецепт — куриный суп.
*Приёмка:* невалидный рецепт красит CI; валидный обновляет `index.json` автоматически.

**Фаза 2 — Приложение.** Весь раздел 4.
*Приёмка:* на S24 FE открывается суп из репозитория; при 2 и 6 порциях количества и склонения верны; вода и лавровый лист не масштабируются; в авиарежиме всё открывается; таймер уходит в «Часы» с подписью шага, не покидая приложение; сессия готовки переживает перезапуск.

**Фаза 3 — Сборка, подпись, установка.** `release.yml`, keystore, релиз v0.1.0.
*Приёмка:* приложение установлено из Releases; новый рецепт, запушенный в `main`, появляется после свайпа вниз.

**Фаза 4 — Канал из чата.** GitHub-коннектор, команды «отправь рецепт в гит» и «обнови рецепт».
*Приёмка:* рецепт, отправленный из чата с телефона, появился в приложении без участия макбука.

## 12. Риски

| Риск | Влияние | Мера |
|---|---|---|
| GitHub-коннектор в Claude не умеет писать файлы | Команда из чата не работает | Запасные пути: Cowork с клоном; вставка JSON через веб-интерфейс GitHub с телефона. Проверяется в фазе 4 |
| Медицинский контекст попадает в публичный репозиторий | Утечка персональных данных | Стоп-слова в CI, имена в секрете, правило по `notes` (раздел 8) |
| Потеря ключа подписи | Нельзя обновить установленное приложение | Резервная копия ключа вне репозитория |
| Кеш GitHub задерживает обновление до нескольких минут | Ожидание после пуша | Допустимо |
| Штатные «Часы» на будущем устройстве игнорируют подпись таймера | Косметика | Подпись дублируется строкой активных таймеров внутри приложения |
